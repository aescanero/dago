# CLAUDE.md — Instructions for Claude Code

## Project: dago

AI graph orchestration system with agentic nodes (LLM call, ReAct, reflection,
tool use, routing, guardrails, subgraphs), event-based communication, three-layer
memory, package catalogue, MCP and A2A registries, OAuth 2.1 with ABAC auth,
and a microfrontend dashboard.

## Principles

**Spec Driven Development.** Four specs as sources of truth:

```
specs/openapi.yaml          → REST API
specs/asyncapi.yaml         → Events (Valkey Streams)
specs/patterns/             → Node and flow patterns (JSON Schema)
ent/schema/                 → Data model (Ent)
```

If there is a discrepancy between spec and code, the spec is right.
All **open source** (BSD-3, MIT, Apache 2.0, PostgreSQL License).

## Agentic protocols

```
MCP     → Agent ↔ Tools        (executor → mcp-registry → tools)
A2A     → Agent ↔ Agent        (agent-registry → Agent Cards)
AG-UI   → Agent ↔ User         (orchestrator → dashboard, WebSocket)
A2UI    → Agent → UI widgets   (node → dashboard, declarative JSON)
```

## Critical rules

**Monorepo:** Single `go.mod`. Imports: `github.com/aescanero/dago/libs/...`.
Service-private code: `services/{name}/internal/`. Shared: `libs/`, `adapters/`.

**Architecture:** Domain (`libs/`) must not import infrastructure.
Ent types must not leave `adapters/storage/`. Thin Gin handlers.

**Communication:**
- Orchestration (orchestrator ↔ executor/router/planner): Valkey events only.
- Support (→ catalog, auth-server, mcp-registry, agent-registry): HTTP.
- Dashboard → orchestrator: REST API + WebSocket (AG-UI).
- Never HTTP between orchestrator ↔ executor/router/planner.

**Flow patterns (edges):** sequential, conditional, parallel, loop, interrupt.
**Node patterns (vertices):** llm_call, tool_use, react, reflection,
router, guardrail, subgraph. JSON Schema in `specs/patterns/`.

**Memory:**
- Working (active execution): Ent + Valkey.
- Episodic (history): Ent.
- Semantic (distilled knowledge): Ent + pgvector.
- Consolidation: background post-execution. Never delete, only supersede.

**Auth:** OAuth 2.1 PKCE (users) + Client Credentials (M2M).
ABAC: resource tags ⊆ effective subject tags. Inheritance via OU tree.
JWT tokens validated locally (JWKS). Propagated in events (`auth` field).

**Packages:** Distribution unit: workflow + skills + tools + UI.
Semver. Published in catalog. Validated before execution.

**Data:** Ent schemas in `ent/schema/`. `go generate ./ent` + `atlas migrate diff`.

**Frontend:** TypeScript strict. shadcn/ui + Tailwind. TanStack Query.
Module Federation for package microfrontends. Tokens in memory.

**Code:** TDD. `fmt.Errorf("ctx: %w", err)`. `goimports` + `golangci-lint`.

**Process:** PRs. Squash merge to `main`. Commits: `<type>: <description>`.

## Workflow

1. The `planner` agent generates the sprint document in `docs/sprints/`.
2. The sprint defines: objective, scope, TODOs with dependencies, traceability matrix.
3. TODO order: specs → tests (Red) → data (Ent) → implementation (Green) → refactor → docs.
4. Each commit references sprint and TODO: `feat: description [SPRINT-XXX #N]`.
5. One PR per sprint. Mandatory review. Squash merge to `main`.
6. On close, complete the result section of the sprint document.
